# 长连接监听方案评估

评估日期：2026-11-11。当前 v0.6.0 保持网页快照轮询；本轮完成方案核对，没有连接真实直播间验证，也没有替换接收器。

## 已核对的路径

1. **Web 端 WebSocket**：blivedm 的 Web 示例使用登录账号的 SESSDATA 建立客户端会话，并示范单房间、多房间和停止清理。它适合继续研究复用现有用户扫码账号，但第三方实现存在不等于本插件的认证、重连和身份字段已验证。尤其需要确认账号/UID 字段缺失或打码时的行为，不能把未知身份当成已知用户写入记忆。
2. **直播开放平台**：同项目的开放平台示例还需要开发者密钥、项目 ID 和主播身份码，不能直接用现有扫码状态替代这些条件。若走这条路径，需要单独的用户配置与主播授权，不作为当前插件的默认安装要求。

参考原始实现：[blivedm 项目说明](https://github.com/xfgryujk/blivedm)、[Web 示例](https://github.com/xfgryujk/blivedm/blob/dev/sample.py)、[开放平台示例](https://github.com/xfgryujk/blivedm/blob/dev/open_live_sample.py)。项目说明明确提示其包未发布到 PyPI，不应直接安装同名 PyPI 包。本轮没有新增依赖或复制该实现。

## 推荐实现边界

- 将接收来源与现有 LiveSession 的唤醒、模型、预览和发送策略分开。长连接只产生经过校验的 RoomEvent，不承担发送或登录持久化。
- 先提供显式可选模式；保留当前轮询入口。认证失败与账号失效应停留在待登录状态，避免循环切换掩盖错误。
- 对心跳、超时、认证响应、压缩消息、分包与合包设置大小和解压上限；断线采用有上限的退避，停止房间时取消所有连接与心跳。
- 轮询与 WebSocket 不同时产生重复候选。来源切换时设置接收起点，统一事件去重，并按房间与当前账号隔离。
- UI 显示实际来源、连接状态和降级原因；恢复失败继续保留监听意图，不伪装成正在稳定接收。

## 切换默认接收器前的验收

- 离线协议测试：认证响应、普通/压缩消息、异常长度、截断包、重复包、未知 UID、停止取消和断线重连。
- 用户提供的授权环境中，以只预览模式验证真实认证、多房间收取、账号刷新、断网恢复、房间切换和重启恢复。
- 对比相同房间的事件数量、延迟、漏消息与重复情况；统计只能陈述实际观测，不能由模拟测试推断真实可用性。
- 通过上述验证后再评估默认替换。现有用户取消的真实直播测试不自动恢复，也不为验证接收器发送测试弹幕。
