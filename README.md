# B 站直播间对话

<img src="logo.png" alt="B 站直播间对话：小电视、弹幕气泡与语音声波" width="160">

一个可独立安装的 AstrBot 插件。它同时读取多个直播间的新弹幕，用 AstrBot 的聊天模型生成短回复，再通过已登录的 B 站账号发回该直播间。

支持多房间同时监听、可自定义唤醒词、AstrBot 人格、独立扫码登录、可选 BiliBot 登录与记忆联动，以及每个房间单独配置的语音和画面识别。

## 安装和使用

在 AstrBot WebUI「插件管理」中选择通过仓库链接安装，输入：

```text
https://github.com/Eason4869/astrbot_plugin_bilibili_live_chat
```

已有旧版时，如果上传 ZIP 提示目录已存在，可用压缩包里的插件目录更新 AstrBot 的 `data/plugins/astrbot_plugin_bilibili_live_chat`，保留 `data/config/astrbot_plugin_bilibili_live_chat_config.json`，然后在 AstrBot 重载插件。

1. 在 AstrBot WebUI 的插件页上传本插件 ZIP，或将 `astrbot_plugin_bilibili_live_chat` 目录放进 `data/plugins/` 后加载。若依赖未自动安装，用 AstrBot 的 Python 环境安装本目录的 `requirements.txt`。
2. 在插件详情里打开「直播间对话」视图。新版面板也可从插件视图入口进入。页面需要支持插件 Pages 或 Views 的 AstrBot，建议使用 4.24.2 或更新版本。
3. 在「账号连接」生成二维码。用 B 站 App 扫码并在手机上确认，页面会自动更新账号状态。已在同一个 AstrBot 实例使用 BiliBot 时，也可以选择「复用 BiliBot」并使用该账号。
4. 在「模型与提示词」选择共享聊天模型和可选的 AstrBot 人格；在「回复策略」添加唤醒词，推荐选择「克制陪伴」。默认唤醒词列表为空，支持忽略大小写与全半角差异的包含匹配。
5. 点击「保存共享设置」，在「直播间」添加数字房间号，最多 20 个。建议先开启「只预览，不发弹幕」再「开始监听」，查看输入与回复符合预期后再关闭预览。每个房间的首批弹幕只建立监听起点。

### 聊天命令

AstrBot 4.5.7 起可使用聊天命令。管理员在私聊发送 `/直播对话` 或 `/直播对话 状态` 可查看状态。发送 `/直播对话 登录` 获取二维码，手机确认后发送 `/直播对话 确认`。使用 `/直播对话 开始 <房间号>` 和 `/直播对话 停止 <房间号>` 管理单个房间；仅有一个房间时可省略房间号。群聊和非管理员会收到操作入口提示。

每个房间的启停选择会写入配置。修改共享设置、重载插件或重启 AstrBot 后，已开启的房间会自动恢复，手动停止的房间保持关闭。账号失效或配置未就绪时，房间会显示「已开启 · 待登录」或「已开启 · 待配置」。网络中断会重试。旧版房间号会自动导入，从未保存过启停选择的房间需开启一次。BiliBot 记忆开关可以在监听中切换。

## 对话设置

- 默认采用「克制陪伴」：唤醒后 30 秒内，仅已使用唤醒词的观众可继续接话；不接其他观众的闲聊。成功回复不自动续时，单轮上限 90 秒。可显式选择全房间接话、续时和上限；再喊唤醒词不会重置活跃窗口的上限。
- 「点名回应」把窗口设为 0，每条都需唤醒词；「话题参与」允许短暂接全房间的话和语音，偶尔附和。预设只填表，点击保存后生效，不改变房间独立覆盖项或模型、提示词。
- 语音默认每次需要明确唤醒，画面默认只辅助回答；识别开关在每个房间设置，是否主动参与由回复策略控制。三种输入共用一个回复通道，不各自排队发一条。
- 同轮按唤醒 > 接话 > 附和保留一个候选；生成期间的普通接话会合并，新的明确唤醒仍保留。更高优先级的输入会淘汰仍未发送的低优先级回复。
- 「没有被喊时，偶尔附和」默认关闭。开启后默认每 300 秒最多尝试一次，采样概率 20%；任何成功回复都会推迟下次附和。明显的提问会跳过，模型也可以选择安静。
- 同一账号下所有直播间共用默认 20 秒发送冷却和每分钟 2 次发送尝试上限。正式回复与附和都计入，发送结果未知的请求不会重发。
- 内置直播间额外提示词始终生效，可在「模型与提示词」查看全文：一句短句、不抢话、不复述、不主动追问，语境不足保持安静。AstrBot 人格与自定义提示词可继续补充风格，两种回复可分别填写偏好。

升级时保留已有窗口、冷却等数值及自定义提示词；新增的接话对象、语音主动参与和画面附和选项缺省采用克制值。希望完整应用推荐参数时，在「回复策略」选择「克制陪伴」并保存。共享修改有待保存提示，刷新状态不会覆盖编辑；「恢复已保存」可撤销共享表单修改。房间配置仍独立保存。

## 可选的 BiliBot 联动

可与 [BiliBot](https://github.com/chenluQwQ/astrbot_plugin_bilibili_ai_bot) 2.0.3 同装。两项联动分别设置。

- **复用登录**。将「B 站登录来源」设为「复用 BiliBot 登录」。先在 BiliBot 中登录。插件从当前运行的 BiliBot 只读获取凭据，不复制到独立插件配置。凭据更换或刷新后，已开启的房间会用新凭据重连。BiliBot 停用时保留各房间的开启选择。若要切回自己的账号，选择「独立登录」。
- **直播记忆**。开启「联动 BiliBot 直播记忆」，即使用独立账号也可以联动。只召回能确认属于当前房间和当前 UID 的直播记忆。成功发送的正式回复会把当条弹幕和回复写到 BiliBot 的直播记忆。附和不读写记忆。BiliBot 未启动或接口不可用时，仍可使用房间的短期上下文对话。

「账号连接」中的「BiliBot 联动兼容检查」分别显示登录配置、记忆读取和记忆写入接口是否存在及参数是否兼容，并显示可获取的插件版本。它不会查询或写入测试记忆，也不代表远端服务已验证；实际登录有效性在建立连接时检查。

## 长连接监听与轮询回退

升级后默认仍使用轮询。要先试用长连接，在目标房间开启「只预览，不发弹幕」，展开「房间独立策略」，取消「弹幕监听方式」的「继承共享」，选择「长连接优先（失败轮询回退）」并保存，再开始监听。也可在「模型与提示词 / 连接与运行参数」统一选择。

长连接自动使用当前选择的独立扫码或 BiliBot 登录，无需另开端口或申请开放平台密钥。初始化和认证期间轮询继续运行；认证成功后由长连接接收，轮询停止交付消息。连接、临时凭证、解码或心跳失败时自动回退轮询，默认等待 60 秒再尝试，连续失败最多退避到 300 秒。经登录接口确认账号失效时进入待登录状态，不用回退掩盖账号错误。

房间卡片会显示实际来源、回退原因、重试倒计时和最近心跳。调试记录中会标明弹幕来自长连接还是轮询。切换来源后第一批轮询只建立起点，使用事件标识及同 UID、内容、服务端时间做有限去重；高流量和切换空档仍可能遗漏消息，不补发历史弹幕。缺失或打码 UID 的消息不作为已知观众处理，不写入记忆。

插件支持带可用 UID 的 `DANMU_MSG` 文字弹幕，不处理礼物等其他业务事件；遇到不支持的新弹幕业务格式时回退轮询。Brotli 解码依赖会随插件安装；缺失或版本过旧时页面显示原因并使用轮询。新依赖安装完成后可重载插件。

已使用离线数据、本机实际 WebSocket 服务和预览模式测试认证、压缩数据、心跳、回退恢复与发送隔离；这不代表已在真实 B 站直播间完成验证。

## 每个房间的独立配置

在房间卡片展开「房间独立策略」，按「唤醒与输入、模型与提示词、低频附和」分组。每项默认「继承共享」；取消后可覆盖模型、人格、唤醒词、接话对象、语音连续接话、画面主动附和、别名、去重、附和偏好和提示词。保存只重连本房间。空的人格选项表示不复用人格；勾选「继承共享」并保存恢复继承。共享修改不覆盖房间已保存的独立项。

可选择其他房间并点击「复制到本房间」，复制对方已保存的对话覆盖项及音视频配置。该操作会替换目标房间这些设置，保留账号、预览开关和监听启停状态。目标房间有未保存编辑时，需先保存或点击「恢复已保存」。复制的是覆盖项；继承项仍跟随共享设置。

共享「窗口外低频附和」始终是总开关：关闭后所有房间都不附和，房间的单独开启不能绕过它。账号发送冷却和每分钟上限继续由各房间共享。

## 识别效果调节

- **语音唤醒别名**：把转写模型常输出的同音词填进列表，每行一个；只用于语音，普通弹幕仍按正常唤醒词匹配。这是自定义文字别名，不会自动识别说话人或生成所有同音词。
- **语音与弹幕去重**：默认 5 秒，0 关闭。同房间合并相同文字及至少 10 字长句的轻微转写差异；保护否定词、中文数字和小数差异，避免误吞新问题。仅为保守文本近似，不能判断真实说话人或语义完全相同；不按此规则合并同来源重复发言。有效唤醒优先于先前附和候选。
- **画面变化阈值**：音视频设置中默认 24，越低越敏感。仅做图像灰度差异比较，不等同于模型理解发生了什么。
- **连续确认帧数**：默认 1，可设 2–5。比较基准与新画面持续不同达到指定帧数后，才产生附和候选。调高会增加至少一个抽帧间隔的确认时间。
- **忽略区域**：每行填写左上角和右下角百分比坐标 `x1,y1,x2,y2`，最多 8 个。例如 `0,80,100,100` 忽略底部 20% 的变化。忽略区域只影响变化检测，看图模型仍收到原始截图。

## 可选的智能附和判断

先在 AstrBot 配置「判断」提供商，再在共享高级设置或房间独立配置中开启「智能附和判断」。模型 ID 留空使用 AstrBot 默认判断提供商；这是判断模型，不是聊天模型。默认阈值 0.7，范围 0.5–1。

只有经过原有附和间隔和概率选中的候选，才会进入判断。判断模型基于当前事件文本和近期上下文决定是否值得接话；画面候选只提供变化事件及文本上下文，此步骤不直接看图，实际视觉理解仍由后面的视觉/聊天模型完成。判断建议安静时不生成回复、不发送弹幕。接口或模型未配置、调用失败、超过 3 秒时，回退到原附和逻辑，调试记录会显示原因及判断耗时。判断与生成分别产生模型用量，仍遵守消息时效、附和总开关、账号限流和只预览模式。

该功能动态检测 AstrBot 的公开 `context.decision.yes_no` 接口；旧版没有此接口时可继续使用其他功能。[AstrBot 判断接口说明](https://docs.astrbot.app/dev/star/guides/ai.html)。

## 实时调试与只预览

在房间卡片开启「只预览，不发弹幕」，再点击「开始监听」。弹幕监听、语音转写、画面识别、唤醒判断和回复生成仍会运行，但结果只显示在控制台，不调用弹幕发送接口，也不写入 BiliBot 长期记忆。模型调用仍会产生用量。预览使用独立的冷却和频率计数，不占用其他房间实际发送的账号预算。预览中的回复会进入本次预览的短期上下文，并按原规则延长接话窗口。

预览开关按房间保存，重载插件或重启 AstrBot 后保留。切换模式会取消该房间正在处理的任务并重新连接；发送接口在切换前已收到的弹幕无法撤回。关闭预览后，已开启的房间恢复实际发送。切换请求的结果无法确认时，页面会显示「状态待确认」，需成功刷新后再操作。

展开「实时调试」可查看：

- 最近的弹幕、语音转写、命中的唤醒词、候选回复，以及实际发送或预览结果。
- 未回复的原因：首批快照、忽略账号、未开启附和、未采样、等待冷却、被新消息替代、消息过期、模型保持安静、格式校验失败或调用失败。
- 最近抽取的直播画面。仅展开的房间读取调试数据，截图变化时才传输新图片。
- 每条记录的采集或抽帧等待、转写前排队、转写、生成前排队（包含冷却）、回复生成（包含看图与记忆召回）、生成后限流等待、发送接口和本机总耗时。未执行的阶段显示「—」，预览没有发送耗时。实际发送和预览分别计算最近完成记录的平均耗时。

调试区默认每 2 秒刷新，可点击「暂停刷新」保留当前内容；暂停页面刷新不会停止后台监听和回复。切换浏览器标签或关闭调试区会暂停拉取。每个房间仅在内存保留本次连接最近 50 条记录，重新连接或重启后清空，不保存音频或历史截图。时间统计使用本机时钟，不能代表 B 站直播传输或观众看到弹幕的完整延迟。

## 音视频识别

在房间卡片展开「语音与画面」，分别开启语音或画面识别。两项默认关闭。插件自动查找运行环境中的 FFmpeg，未找到时使用 imageio-ffmpeg 依赖中携带的程序。首次安装或升级时请等待 AstrBot 完成依赖安装。保存只重新连接该房间，保留启停选择。

「模型与提示词 / 连接与运行参数」可查看 FFmpeg 路径，或手动指定程序文件或 bin 目录。远端或 Docker 部署时填写远端机器或容器内路径。少数没有兼容依赖包的系统仍需安装 FFmpeg 后指定路径。更新后如果尚未安装依赖，可从插件管理执行依赖安装后重载。

- **语音**使用 AstrBot 默认语音识别，也可选其他已配置模型，片段上限默认 6 秒。默认只有转写命中唤醒词才回应，其他语音留作上下文；开启「语音连续接话与附和」后才允许普通语音主动参与。公开直播流可能包括主播、嘉宾和播放内容，转写不代表已确认的 B 站账号身份。
- **画面**默认每 5 秒抽帧，使用当前聊天模型或另选支持图片输入的模型。默认仅在正式回复涉及画面时调用；开启「画面变化主动附和」后，明显变化还可参与低频附和。看图失败会提示，普通文字仍可继续。
- **低频附和**间隔和概率可按房间覆盖，留空继承共享。所有输入受共享附和总开关约束，语音和画面还有各自的主动参与选项；所有回复遵守账号冷却和每分钟上限。
- 转写使用短时 WAV，处理后清理，视频只保留近期帧。使用云端语音或视觉提供商时，相关片段或截图会交给所选提供商。断流时媒体通道单独重试，关闭房间时停止拉流。语音和视频同时开启会分别拉取音轨与画面。

## 环境自检

在控制台顶部点击「环境自检」，选择共享默认配置或某个房间，点击「开始自检」。使用房间时会采用该房间保存的语音和视觉模型覆盖项。检查过程中可以查看每一步的状态和耗时，单项失败后继续检查其余项。

- FFmpeg 会实际运行，读取内置 H.264/AAC 测试素材，验证音轨提取和 JPEG 抽帧。
- 语音模型会收到一段内置测试语音，并显示转写结果。
- 视觉模型会收到一张生成的数字图片，检查是否能正确读取图片内容。

模型检查会产生少量模型用量，失败原因会脱敏后显示在页面。自检在远端 AstrBot 进程中运行；重载或停用插件时会取消未完成的检查。

## 验证与来源

本插件支持长连接优先及网页弹幕快照轮询。轮询时两次读取之间滚出快照的弹幕可能收不到。真实可用性取决于 B 站接口和账号状态。可先在自己的授权环境用只预览模式检查接收、唤醒和回复；本轮开发未发送真实测试弹幕。

## 开发验证

将仓库克隆为 `astrbot_plugin_bilibili_live_chat` 目录，并在其父目录运行：

```sh
python -m pip install -r astrbot_plugin_bilibili_live_chat/requirements.txt ruff
python -B -m unittest discover -s astrbot_plugin_bilibili_live_chat/tests
ruff check --no-cache astrbot_plugin_bilibili_live_chat
node --check astrbot_plugin_bilibili_live_chat/pages/live-chat/app.js
node --check astrbot_plugin_bilibili_live_chat/pages/live-chat/debug.js
node --check astrbot_plugin_bilibili_live_chat/pages/live-chat/room-settings.js
```

测试使用模拟的 AstrBot、模型和直播接口，不会发送真实弹幕。真实直播间端到端验证尚未进行。

安装 Chrome 或 Edge 后，还可以运行可选的浏览器回归：

```sh
node astrbot_plugin_bilibili_live_chat/tests/webui_smoke.mjs
```

脚本在 Windows 默认使用 Edge，Linux 默认使用 `/usr/bin/google-chrome`；也可通过 `BROWSER_BIN` 环境变量指定浏览器程序。它只使用本机模拟数据，检查预览切换、房间隔离、暂停刷新、过期请求、响应丢失、文本安全渲染和移动端布局。

长连接监听的实现范围及真实环境验证要求见 [监听机制说明](docs/LISTENER_ROADMAP.md)，协议参考和许可见 [第三方说明](THIRD_PARTY_NOTICES.md)。
